# C题补充文献调研与建模建议

> 检索日期：2026-08-07。来源优先采用 arXiv 原文、期刊 DOI/机构主页和官方 GitHub 仓库。本文的目标不是堆文献，而是筛出能直接支撑问题1—4建模、公式和实验设计的材料。

## 一、总体结论

DeepSeek 的《文献与方法论综述》方向基本正确，且抽查的 2025—2026 年关键 arXiv 条目确实存在。不过，原清单偏重新近预印本、偏轻经典工作，而且没有明确区分“可以引用来说明研究背景”和“可以直接借用模型结构”的文献。

本题最稳妥的技术主线仍然是：

1. 问题1采用可解释的小时级时间序列预测，并以季节性朴素模型作为基线；
2. 问题1、2使用任务级不可抢占调度模型；
3. 问题2把任务的时空迁移与电价、碳强度、新能源耦合；
4. 问题3使用线性储能能量平衡和 SOC 递推；
5. 问题4建立任务—电力—储能联合 MILP，以 ε-约束或归一化加权和得到多目标权衡；
6. 只有在需要讨论多主体利益冲突或动态电价机制时，才引入 Stackelberg 博弈。

## 二、最值得使用的核心文献

### 1. 问题1：负荷预测

#### A Physics-Aware Framework for Short-Term GPU Power Forecasting of AI Data Centers

- arXiv:2605.04074，2026。
- 提出 PI-DLinear，将 GPU 计算、内存利用率、温度和功率联系起来，预测范围为 5—80 分钟。
- 用处：可在问题1相关工作中说明 AI 数据中心负荷具有突发性、异构性；DLinear 可作为时间序列模型候选。
- 局限：本文预测的是分钟级 GPU 功率，而赛题要求的是小时级“到达 GPU 需求”，且附件没有温度、GPU利用率等物理变量。因此不能照搬其 physics-aware 部分。
- 链接：https://arxiv.org/abs/2605.04074

#### Deployment-Efficient Short-Term Load Forecasting in AI Data Centers via Sequence-to-Point Knowledge Distillation

- arXiv:2605.00681，2026。
- 使用 MIT Supercloud 数据，研究突发、非平稳的 AI 数据中心短期负荷预测。
- 用处：支撑“AI负荷非平稳、需要滚动预测”的动机。
- 局限：知识蒸馏并不是赛题的必要复杂度，数据量和预测任务也不要求部署压缩。
- 链接：https://arxiv.org/abs/2605.00681

#### 实际建议

问题1主模型建议使用 LightGBM/XGBoost 或 DLinear，至少设置 seasonal-naive 基线。不要仅为了“高级”而使用 Transformer。赛题预测窗口只有24小时，训练序列约2376点，复杂深度模型容易过拟合且不便解释。

### 2. 问题2：碳感知时空调度

#### Let's Wait Awhile: How Temporal Workload Shifting Can Reduce Carbon Emissions in the Cloud

- arXiv:2110.13234，2021。
- 研究具有截止时间的可延迟任务如何迁移到低碳时段，并分析预测误差的影响。
- 用处：直接支撑批量推理和训练任务的“时间迁移”；可借鉴不同 deadline/slack 下的减排敏感性实验。
- 链接：https://arxiv.org/abs/2110.13234

#### On the Limitations of Carbon-Aware Temporal and Spatial Workload Shifting in the Cloud

- arXiv:2306.06502，2023。
- 使用123个区域的碳强度数据分析交互式和批量负荷，指出实际减排上限受到截止时间、SLO和区域差异限制，且简单策略有时已能获得大部分收益。
- 用处：非常适合解释问题2中“碳减排不能无限追求，必须考虑时延和服务质量”；也支持设置简单启发式基准。
- 链接：https://arxiv.org/abs/2306.06502

#### CarbonScaler: Leveraging Cloud Workload Elasticity for Optimizing Carbon-Efficiency

- arXiv:2302.08681，2023。
- 利用批任务的时间弹性减少碳排放，并讨论完成时间约束。
- 用处：可以支撑“不同任务类型具有不同调度弹性”的分类思路。
- 局限：CarbonScaler允许动态调整资源，赛题任务不可拆分、不可抢占，因此不能照搬其动态资源缩放算法。
- 链接：https://arxiv.org/abs/2302.08681

#### CASPER: Carbon-Aware Scheduling and Provisioning for Distributed Web Services

- arXiv:2403.14792，2024；代码仓库 carbonfirst/casper。
- 面向分布式在线服务，将时延敏感服务的部署与碳感知结合。
- 用处：支撑实时推理任务的低时延优先与空间迁移限制。
- 代码：https://github.com/carbonfirst/casper

### 3. 问题3：储能优化

#### Optimal Battery Charge Scheduling For Revenue Stacking Under Operational Constraints Via Energy Arbitrage

- arXiv:2305.04566，2023。
- 用处：SOC递推、充放电功率约束、电价套利和多收益目标均可作为问题3的标准建模参考。
- 本题落地：保留充放电效率、SOC上下限、功率上限与终端SOC约束；增加新能源直供、充电、外送和弃电变量。
- 链接：https://arxiv.org/abs/2305.04566

#### Watts vs. Bytes: Turning Data Centers into Grid Assets via Storage Compute Co-Optimization

- arXiv:2605.16190，2026。
- 联合考虑 deadline-constrained computing、BESS、峰值与爬坡约束。
- 用处：与问题4高度贴合，可借鉴“计算柔性 + 储能柔性共同缓解并网容量限制”的解释框架。
- 局限：论文考虑 DVFS、辅助服务和电池退化，均超出本赛题要求；不应全部加入。
- 链接：https://arxiv.org/abs/2605.16190

### 4. 问题4：算—储—电联合优化

#### Carbon-Aware Compute–Power Scheduling for AI Data Centers with Microgrid Prosumer Operations

- arXiv:2605.03751，2026。
- 使用 MILP 联合建模刚性训练任务、弹性推理、储能、双向电网交互、时延、连续执行和碳预算。
- 用处：这是与题面最接近的一篇文献，最适合作为问题4模型结构参考。
- 可借用的骨架：任务指派、开工、连续占用、功率平衡、电池SOC、购售电、碳预算。
- 注意：其数据与实验是合成且“practically motivated”，需要用赛题附件重新定义参数，不能照搬结果。
- 链接：https://arxiv.org/abs/2605.03751

#### A Novel Hierarchical Co-Optimization Framework for Coordinated Task Scheduling and Power Dispatch in Computing Power Networks

- arXiv:2508.04015，2025/2026修订。
- 两阶段框架：日前随机机组组合 + 实时电力调度和 DRL 任务调度，并考虑边际碳强度。
- 用处：适合写“算力网络与电网协同”的研究背景和分层求解思路。
- 局限：本题没有发电机组组合和电网潮流，直接使用该两阶段框架会扩大题目边界。
- 链接：https://arxiv.org/abs/2508.04015

#### Contextual Robust Optimization for AI Data Center Scheduling with Statistical Guarantees

- arXiv:2606.17466，2026。
- 处理工作负载与新能源预测误差，使用上下文鲁棒优化、联合机会约束和有限样本可行性保证。
- 用处：适合作为问题4新能源波动场景或鲁棒性扩展。
- 建议：正文主模型先做确定性 MILP，场景分析再加入 ±20% 新能源扰动；若时间充足，再做预算不确定集，不必直接复现完整机会约束。
- 链接：https://arxiv.org/abs/2606.17466

#### GreenSlot: Scheduling Energy Consumption in Green Datacenters

- SC 2011 的经典绿色数据中心调度工作。
- 在太阳能、电价和任务截止时间约束下调度并行批任务。
- 用处：为“根据可再生能源和电价移动具有截止时间的计算任务”提供经典依据，弥补现有清单过度依赖新预印本的问题。
- 链接：https://personals.ac.upc.edu/jguitart/HomepageFiles/SC11.pdf

## 三、导师 Hangxin Li 的博弈论文是否有用

### 论文信息

Rui Tang, Shengwei Wang, Hangxin Li, “Game theory based interactive demand side management responding to dynamic pricing in price-based demand response of smart grids,” Applied Energy, 250 (2019), 118–130. DOI: 10.1016/j.apenergy.2019.04.177。

- 机构全文：https://ira.lib.polyu.edu.hk/bitstream/10397/95383/1/Tang_Game_Theory_Based.pdf
- 导师主页：https://research.polyu.edu.hk/en/persons/hangxin-li/

### 核心结构

论文把电网设为 Stackelberg leader，把多个响应型建筑设为 followers：

- 电网先发布动态电价，目标是提高自身净收益并降低需求波动；
- 各建筑根据价格调整逐时用电，目标是降低电费并控制偏离基准需求的不利影响；
- 通过领导者—跟随者均衡寻找电网与用户的双赢互动策略；
- 论文还讨论预测不确定性下的增强策略。

### 与本题的对应关系

| 导师论文 | 本题可对应对象 |
|---|---|
| 电网 leader | 动态电价制定者或区域能源运营者 |
| 建筑 followers | 六个数据中心区域或算力运营者 |
| 建筑需求响应 | 任务迁移、延迟开工、储能充放电 |
| 降低需求波动 | 区域净购电峰值和负荷波动 |
| 建筑电费 | 数据中心运行成本 |

### 判断

有用，但不是题目默认条件下的必需主模型。

原因是题目给出的电价是外生输入，并没有要求电网决定电价；六个区域也没有明确设定为具有独立利益的竞争主体。因此，把问题1—4全部改成博弈模型会引入题面未给出的效用函数和议价机制，增加不可验证的假设。

最合适的用法有三种：

1. 在问题4“不同电价机制”场景中增加一个动态定价扩展：电网为 leader，数据中心聚合体为 follower；
2. 用论文的思想解释峰谷电价如何诱导任务迁移和储能响应；
3. 在讨论部分指出，集中式联合优化假设统一运营者，若未来转向多主体市场，可扩展为 Stackelberg 双层模型。

不建议把它作为问题2或问题4唯一求解框架。竞赛主线应保持集中式 MILP，多主体博弈作为加分扩展即可。

## 四、值得参考的 GitHub 仓库

### sustainablecomputing/caspian

- 多 Kubernetes 集群的碳感知任务放置与调度，使用未来碳强度、集群容量和任务状态调用优化器。
- 最值得参考：按时隙滚动调度、空间放置和碳强度接口的程序结构。
- 链接：https://github.com/sustainablecomputing/caspian

### carbonfirst/casper

- 分布式在线服务的碳感知调度和容量配置。
- 最值得参考：时延敏感负荷与碳排目标之间的权衡。
- 链接：https://github.com/carbonfirst/casper

### HewlettPackard/sustain-cluster

- 多区域可持续数据中心调度仿真环境，包含 GPU、价格、碳强度、时延、SLA 和规则/RL基线。
- 最值得参考：状态、动作、评价指标以及 lowest-carbon、lowest-price、most-available 等基线设计。
- 注意：仓库范围比赛题更大，不建议直接移植其 RL；可借用基线和实验组织。
- 链接：https://github.com/HewlettPackard/sustain-cluster

### tum-ens/urbs

- 基于 Pyomo 的分布式能源系统线性优化模型，支持储能。
- 最值得参考：能源平衡、储能建模和结果组织方式。
- 链接：https://github.com/tum-ens/urbs

## 五、建议最终保留的引用组合

为了避免参考文献过多但没有实际作用，建议正文重点引用约 10—14 篇：

- 问题1：AI数据中心短期预测2篇 + 一篇通用时序预测方法；
- 问题2：Let's Wait Awhile、Limitations、CASPER、CarbonScaler；
- 问题3：电池套利/SOC论文1—2篇；
- 问题4：2605.03751、2508.04015、Watts vs. Bytes、GreenSlot；
- 扩展讨论：Hangxin Li 等的 Stackelberg 需求响应论文；
- 多目标方法：NSGA-II或 ε-constraint 只需选择一种核心方法引用，不必同时堆叠多种进化算法。

## 六、对当前建模方案的直接建议

1. 主模型用 MILP，而不是直接采用强化学习或博弈。附件提供完整确定性数据，MILP更透明、可验证，也更容易给出硬约束满足证明。
2. 问题2、4设置至少四个可解释基线：就地立即执行、最低电价、最低碳、综合优化。
3. 问题4用 ε-constraint 比单一主观权重更有说服力：例如最小成本，同时设置不同碳预算、时延上限和峰值上限，绘制成本—碳排 Pareto 曲线。
4. 导师博弈论文可用于“电价机制”扩展：用 Stackelberg 模型生成动态价格，再让集中式调度模型响应；正文须清楚区分题目给定电价场景与扩展动态定价场景。
5. 不要把论文中与题面不一致的机制带进来，包括任务抢占、DVFS、传输能耗、带宽限制、线路潮流、发电机组组合和电池退化成本，除非作为局限或未来工作。
